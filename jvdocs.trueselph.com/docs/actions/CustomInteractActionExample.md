# Custom Interact Action Example

You can create your custom actions for your agent. This example shows how to create an interact action that queries a server hosting a VLM and gets a response.

This example assumes that an agent exists in the daf folder (under jivas or anonymous sub-folder)

## Getting the Custom Action boiler plate

To get a boiler plate code for the custom interact action, run the following command:

```sh
jvcli create action --name vlm_query_interact_action --type interact_action
```

Note that the action_name must be in snake case and all characters must be in lower case
This will create the interact action with all defaults in place. However, we can customize the parameters this command offers and create other kinds of actions. For a full list run the following command

```sh
jvcli create action --help
```

Once, the action is created, it appear under the following folder.

```sh
actions/anonymous/vlm_query_interact_action
```

## Graph Visualization of Action

Here we present a simplified graph representation of how the nodes are arranged. The following entities are nodes:

- Agent
- Actions
- vlm_query_interact_action (This is the custom action you created)

Agent -> Actions -> vlm_query_interact_action

So, an interact_walker(the walker to traverse the Jivas graph) first would visit the Agent, then the node connecting to all its actions (i.e. Actions node) and then the specific `vlm_query_interact_action` node.

## Action Directory Files

Here is a full list of files that we are going to find in this directory

- info.yaml: This is contains information on the action itself and some configuration properties.
- lib.jac: This file is like a global file that includes all the walkers and action nodes. By default it will only include the action node. However, walkers for this action node should be added here.
- vlm_query_interact_action.jac This is the actual action file generated by the jpr. This is where the actual implementation of the action node should be.

## Action Parameters

```sh
has base_URL: str = "";
has save_endpoint: str = "";
has query_endpoint: str = "";
```

To make this action general we take three parameters, baseURL of the server hosting the VLM, the `save enpoint` for saving the image to be queried upon and the `query endpoint` for the actual query.

## on_register

The on register ability is executed then the action is registered for the agent. In our case, we set it to default values like the following:

```sh
can on_register() {
        # ability that runs after registration of action
        if (not self.base_URL) {
            base_URL = "http://127.0.0.1:3000/";
        }

        if (not self.save_endpoint) {
            save_endpoint = "walker/save_image";
        }

        if (not self.query_endpoint) {
            query_endpoint = "walker/query";
        }
}
```

## on_enable

The on_enable ability runs when the action is enabled in the agent. For our purposes, we simply copy the content of on_register for the on_enable function.

## Internal action abilities

For the functioning of our action, we have created some internal functions that are called to perform the intent of the action.
For our purposes, we call this function `query`

```sh
can query(files: list[UploadFile], utterance: str) -> dict {
        # query the VLM with the given files and utterane and return the response.

        # Save the image files
        if not files {
            return {"response": "No files provided."};
        }
        file_list = [];
        for file in files {
            file_list.append(("images", (file.get('name'), file.get('content'), file.get('type'))));
        }
        save_image_response = requests.post(
            url = self.base_URL + self.save_endpoint,
            files = file_list
        ).json();

        url_list = save_image_response.get('reports')[0]["urls"];
        # Query with file URLs
        query_response = requests.post(
            url = self.base_URL + self.query_endpoint,
            json = {
                "image_urls": url_list,
                "prompt": utterance
            }
        ).json();

        return query_response.get('reports')[0]["response"];
    }
```

This ability expects a list of `UploadFile` objects(fast-api) and a prompt. First, it saves the images in the server by calling the save endpoint and then it calls the query endpoint with the received file urls and the prompt.

## Execute ability

The execute ability contains the logic for the interact_graph_walker to access this node. This is the ability that is called by the interact_graph_walker. For our action node we take the files using `data_items` and the query using the `utterance`. Here is the concrete implementation

```sh
can execute(visitor: interact_graph_walker) -> dict {
    # override to implement action execution
    # Call query with interact_graph_walker attributes
    data_items = visitor.interaction_node.get_data_items();
    visitor.context_data[f"{self.get_type}_VLM_response"] = query(data_items, visitor.utterance);
}
```

## Action Walkers

To try out the capabilities of our action, we can create standalone walkers that interact with the action. We must create these walkers in the same action folder and include it in `lib.jac`.

For this action, we have created a walker in `query_vlm.jac` file that is called `query_vlm`. The walker takes in the following parameters:

- files
- utterance
- response

The response parameter is what is set as the response of the action node. The concrete implementation is as follows:

```sh
import:py from fastapi {UploadFile}
import:jac from jivas.agent.core.agent { Agent }
import:jac from jivas.agent.action.action { Action }
import:jac from jivas.agent.action.actions { Actions }
import:jac from jivas.agent.action.interact_graph_walker { interact_graph_walker }

walker query_vlm :interact_graph_walker: {
    # query action for VLM
    has files: list[UploadFile] = [];
    has utterance: str = "";
    has response: str = "";

    can on_agent with Agent entry {
        visit [-->](`?Actions);
    }

    can on_actions with Actions entry {
        visit [-->](`?Action)(?enabled==True)(?label=="VlmQueryInteractAction");
    }

    can on_action with Action entry {
        print("Querying VLM with files and utterance");
        self.response=here.query(self.files, self.utterance);
    }
}
```

## Action parameters

The action has now been created and we must add it to our agent. To do so, we navigate to the agent's directory we want to add the file to and to the `descriptor.yaml` file. Now, we simply add the following:

```sh
action: anonymous/vlm_query_interact_action
    context:
      version: "0.0.1"
      enabled: true
      base_URL: "http://127.0.0.1:3000/"
      save_endpoint: "walker/save_image"
      query_endpoint: "walker/query"
```
